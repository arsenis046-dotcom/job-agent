# Мастер-профиль: что значит каждое поле

`profile/master_profile.yaml` — единственный источник фактов обо мне.
Описания полей живут здесь, а не в комментариях YAML: файл перезаписывается
программой (`jobagent profile build`), и комментарии при этом теряются.

Начать:

```bash
cp profile/master_profile.example.yaml profile/master_profile.yaml
```

**Сам профиль и файлы проектов в репозиторий не попадают** — они в
`.gitignore`. Это личные данные: имя, телефон, почта, а в описаниях
проектов нередко и внутренние системы работодателя. Отслеживаются только
пустая схема `master_profile.example.yaml` и шаблон
`profile/projects/_template.yaml`. Приватную ссылку на репозиторий
в `repo_url` писать не нужно: для рекрутера она выглядит битой, и лучше
оставить поле пустым или дать публичное демо.

Правило чтения файла: **`null` и пустой список — это «факт неизвестен»**,
а не «нечего писать». Агент обязан задать вопрос, а не домыслить.

## person

| Поле | Что это |
|---|---|
| `full_name` | полное имя, как в резюме |
| `city` | город, где я нахожусь |
| `relocation` | готовность к переезду: `true`, `false` или фраза вроде «по договорённости». В резюме не печатается, это фильтр поиска |
| `remote_only` | только удалённая работа |
| `email`, `phone`, `telegram` | контакты. Хотя бы один обязателен |
| `github`, `website` | ссылки. Для пет-проектов GitHub важнее почты |

## position

| Поле | Что это |
|---|---|
| `target_titles` | как должна называться должность. Первый вариант идёт в резюме, остальные — для поиска |
| `level` | `junior` или `middle`. Честно: завышенный уровень отсеется на первом же разговоре |
| `salary_expectation` | строка или число |
| `employment` | полная, частичная, проектная |
| `schedule` | удалённо, гибрид, офис |

## summary

Две-три фразы о себе. Только проверяемые утверждения: что я делаю и чем.
Без «амбициозный, нацеленный на результат» — это не факт.

## employment_history

Места работы: `position`, `company`, `period` (как писать в резюме),
`started` и `ended` в формате ГГГГ-ММ для сортировки, `duties`,
`achievements`. Раздел «Опыт работы» печатается в резюме, только если
список непустой.

`period` — отдельное поле не для красоты: собирать «январь 2025 — настоящее
время» из `2025-01` и `null` означало бы придумать текст, которого в профиле
нет, а это ровно то, что резюме делать не должно.

## projects

Главный актив. Описание либо здесь, либо отдельным файлом в
`profile/projects/<slug>.yaml` (шаблон — `_template.yaml`); файлы
подхватываются автоматически, `slug` не должен повторяться.

В резюме попадает только проект, у которого заполнены **name, one_liner,
stack, my_role** — иначе о нём нечего сказать по делу.

| Поле | Что это |
|---|---|
| `context` | **где сделано**: рабочая задача или свой проект. Обязательно: это первый вопрос работодателя, и подмена лжива в обе стороны |
| `one_liner` | одна фраза: что это и для кого |
| `my_role` | что именно сделал я. Если проект писался не в одиночку — так и писать |
| `result` | измеримый результат, **только если он измерен**. «Ускорил на 30%» без замера — выдумка |
| `in_production` | работает ли у живых людей |
| `repo_url` / `demo_url` | ссылка. Проект без ссылки звучит голословно |
| `learned` | чему научился — пригодится сопроводительному письму |

## skills

Пять групп: `languages` (языки программирования), `tools`, `platforms`,
`databases`, `other`. В резюме печатаются только непустые группы.

Формулировать можно словами из вакансии — **но только те навыки, которые
действительно есть**. Это разрешённый способ пройти ATS; вписывать
отсутствующее — нет.

## languages, education, certificates, constraints

`languages` — язык и уровень владения. `education` — учебное заведение,
специальность, годы, степень. `certificates` — название, кем выдан, год,
ссылка. `constraints` — компании и отрасли, куда не хочу, и свободные
заметки; в резюме не попадает, используется при отборе вакансий.

## Как это проверить

```bash
uv run jobagent profile check   # что заполнено, чего не хватает
uv run jobagent resume          # собрать DOCX, PDF и проверить ATS-читаемость
```

`profile check` возвращает код 1, если не хватает обязательных фактов, —
это удобно для расписания.
