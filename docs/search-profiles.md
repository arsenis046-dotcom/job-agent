# Профили поиска: как сменить сферу, не трогая код

Вся специфика сферы живёт в `config/search_profiles/<имя>.yaml`. Переход
в другую сферу — это другой такой файл, а не правка программы. Это
требование ТЗ, и оно проверяется тестом: `tests/test_sphere.py` создаёт
профиль «повар» и прогоняет по нему весь конвейер — поиск, оценку, отчёты.

## Команды

```bash
jobagent profile list          # какие профили есть, звёздочка — активный
jobagent profile show          # активный профиль целиком
jobagent profile switch povar  # сменить активный
jobagent profile new povar -k "повар" -k "повар горячего цеха" --title "Повар"
```

`profile new` создаёт файл, сразу проверяет его валидность и говорит, что
из мастер-профиля переносится в новую сферу. Без `--keyword` спрашивает
ключевые слова по одному. Существующий файл не затирает.

## Поля

| Поле | Что делает |
|---|---|
| `keywords` | по ним идёт поиск на площадках. Обязательно хотя бы одно |
| `exclude_keywords` | отсев по названию **до** обращения к модели: дешёвый фильтр |
| `must_have_skills` | без этого вакансия не подходит; вес в оценке — 25 |
| `nice_to_have_skills` | приятный плюс; вес 10 |
| `salary_min` | ниже этого — пробел в оценке, вес 15 |
| `schedule` | формат работы: вес 15 |
| `deal_breakers` | фразы-стоп-факторы: вакансия отбрасывается независимо от оценки |
| `score_threshold` | порог этой сферы. Он важнее общего порога в `settings.yaml` |

## Почему стоит заполнить больше, чем keywords

Локальная оценка складывается из слагаемых, и слагаемые берутся из этого
файла. Если заданы только ключевые слова, работают два слагаемых из шести,
и вакансия получает сто баллов за два совпавших слова. Поэтому при
незаполненном профиле оценка ограничена 75, вердикт не поднимается выше
«спросить», и в обоснование пишется, почему. Заполните зарплату, формат
и обязательные навыки — потолок снимется.

## Чего профиль поиска не делает

Он не добавляет фактов обо мне. Если в новой сфере у меня нет ни навыков,
ни проектов, `profile new` так и скажет: «из мастер-профиля в эту сферу
напрямую не переносится ничего». Резюме для такой сферы придётся строить
на других фактах, и их нужно внести в `profile/master_profile.yaml` —
иначе Resume Writer откажется собирать резюме, а не придумает опыт.

Оценка в чужой сфере будет низкой, и это правильно: агент не должен
уверенно советовать откликаться туда, где у меня ничего нет. В тесте
`test_весь_конвейер_работает_на_профиле_вне_it` вердикт `apply` для
поварских вакансий с айтишным мастер-профилем прямо запрещён.
