# Ключ приложения SuperJob: что заполнять и что я нашёл в правилах

Прочитаны «Правила оказания услуг по предоставлению прав использования
API SuperJob» — https://www.superjob.ru/info/api_service.html, проверено
29.10.2026. Форма заявки (https://api.superjob.ru/register) открывается
только после входа в аккаунт, поэтому саму форму я не видел: ниже поля,
которые перечислены в правилах, и готовый текст под них.

## Поправка к тому, что я говорил раньше

Я написал в `docs/api_notes.md`, что регистрация приложения у SuperJob
«самостоятельная, без модерации под работодателя». Это было сказано по виду
сообщения об ошибке, а не по правилам. Правила говорят иначе:

> Заявка на регистрацию Приложения заполняется и направляется Лицензиару
> с использованием онлайн-формы… **При условии уплаты лицензионного
> вознаграждения** Лицензиару и надлежащего заполнения формы заявки
> на регистрацию Приложения, Лицензиату направляется ответ с присвоенным
> Приложению Ключом доступа.

То есть это **заявка, которую рассматривают**, и выдача ключа увязана
с уплатой вознаграждения. Размер вознаграждения в правилах не назван,
отдельной страницы с тарифами на API я не нашёл (`api_license.html`
отдаёт 404, а `doc/api2-public/` — 403 без входа). Возможно, для простого
соискательского приложения плата нулевая — но утверждать это я не могу,
и выяснится это на самой форме.

Что это значит для плана: SuperJob по-прежнему единственная площадка,
где отклик соискателя доступен официально, но «ключ получается
самостоятельно за пять минут» — моё преувеличение. Это такая же заявка,
как у hh.ru, только, похоже, с деньгами вместо модерации.

## Поля заявки (по правилам)

| Поле | Что писать |
|---|---|
| Название Приложения | `Job Agent` |
| Описание Приложения | текст ниже |
| Идентификатор Приложения | `job-agent` (строка, по которой площадка узнаёт приложение) |
| **Ссылка на сайт Приложения** | **нужна страница в интернете — см. ниже** |
| Контактное лицо | твоё имя |
| Адрес электронной почты | твоя почта, на неё придёт ключ |

### Описание

> Приложение для личного использования одним человеком — мной, автором,
> зарегистрированным на SuperJob как соискатель. Помогает мне искать работу:
> находит вакансии по моим ключевым словам, сравнивает их с моим резюме,
> показывает мне список с обоснованием и по моему подтверждению отправляет
> отклик с сопроводительным письмом.
>
> Используемые методы: `GET /2.0/vacancies/` и `GET /2.0/vacancies/:id/`
> для поиска и чтения вакансий, `GET /2.0/user_cvs/` для списка моих резюме,
> `POST /2.0/send_cv_on_vacancy/` для отклика, `GET /2.0/messages/` для
> чтения ответов работодателей.
>
> Приложение работает локально на моём компьютере, публичного веб-интерфейса
> не имеет, других пользователей у него нет. Материалы из базы данных
> SuperJob никому не показываются и не передаются: единственный получатель —
> я. Запросы идут по одному, с паузами, с суточным лимитом откликов.
> Вакансии, пропавшие из выдачи, удаляются из локального кэша.

## Про обязательную ссылку на сайт приложения

Локальной программе сайт не нужен, а поле обязательное. Самый дешёвый
и полезный выход — **выложить репозиторий Job Agent на GitHub публично**
и указать ссылку на него.

Это закрывает сразу две дырки:

1. поле «Ссылка на сайт Приложения» в заявке;
2. **в резюме у тебя ни одной публичной ссылки.** Три репозитория приватные,
   у ботов репозиториев нет вовсе, и единственная живая ссылка — форма
   «Анкеты». Для вакансий про разработку это главная слабость портфолио:
   рекрутеру нечего открыть.

Job Agent для этого подходит лучше всех остальных проектов: в нём нет ни
внутренних систем организации, ни персональных данных, ни секретов —
`.env` в `.gitignore`, мастер-профиль можно оставить незаполненным или
не выкладывать вовсе.

Если выкладывать не хочешь, в поле сойдёт любая твоя страница с описанием
приложения; но тогда вопрос публичных ссылок в резюме остаётся открытым.

## Ограничения правил, которые касаются кода

Явного запрета, как п. 4.6 у hh.ru («не передавать данные сторонним
сервисам»), в правилах SuperJob нет. Но есть близкие пункты, и их стоит
держать в голове:

- **нельзя использовать API «без осуществления взаимодействия с Базой данных
  в режиме реального времени… за исключением разрешенного кэширования».**
  Мы храним вакансии в локальной базе — это кэш. Что именно считается
  «разрешенным кэшированием», сказано в Документации, а она за входом (403),
  так что точного срока я не знаю. Наш `prune` с порогом 14 суток выглядит
  разумно, но это моя догадка, а не вычитанное правило.
- **нельзя показывать Материалы за пределами Приложения** и раскрывать
  полученную информацию о Пользователях в целях, не предусмотренных
  правилами. Отчёты в `output/` — для меня одного, наружу не уходят.
- запрет на автоматические рассылки касается **резюме** («Запросов
  в отношении размещенных в Базе данных SuperJob Резюме с целью
  распространения СПАМа»), то есть работодательской стороны. Отклики
  соискателя под этот запрет не попадают — наш случай правилами не запрещён.
- при прекращении договора ключи нужно **немедленно удалить**.

## Что спросить у них заодно

Если на форме не будет видно размера вознаграждения, стоит спросить
в обратной связи: нужна ли плата за ключ для личного соискательского
приложения без публичного доступа, и какой срок кэширования вакансий
считается разрешенным. Второй вопрос прямо влияет на то, с какой частотой
нам ходить в API и как часто чистить базу.
