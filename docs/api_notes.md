# Что реально доступно соискателю в API площадок

Проверено **29.10.2026** живыми запросами с рабочего ПК (не по памяти).
Проверочная команда у каждого пункта — можно перепроверить в любой момент.

## Итог одной таблицей

| Площадка | Поиск вакансий | Текст вакансии | Отклик от соискателя | Режим в `settings.yaml` |
|---|---|---|---|---|
| hh.ru | только с токеном приложения (403 без него) либо официальный RSS | только по токену | `POST /negotiations` есть, но нужен тот же токен | `access: rss`, `apply: draft` |
| SuperJob | `GET /2.0/vacancies/` с ключом приложения | да, в выдаче и по `/vacancies/:id/` | **есть**: `POST /2.0/send_cv_on_vacancy/` | `access: api`, `apply: api` |
| Работа.ру | партнёрский API, самостоятельной регистрации нет | — | — | выключена |

## hh.ru

**Публичный поиск закрыт с апреля 2026.** Без токена приложения вся выдача
отдаёт 403:

```
$ curl -s -o /dev/null -w '%{http_code}' "https://api.hh.ru/vacancies?text=python&per_page=1"
403   {"errors":[{"type":"forbidden"}]}

$ curl -s -o /dev/null -w '%{http_code}' "https://api.hh.ru/areas/113"
200   # справочники живы
```

Под 403 ушли `/vacancies`, `/vacancies/{id}`, `/employers/{id}`. Живы
`/areas`, `/dictionaries`, `/suggests`. Подмена User-Agent не помогает:
с браузерным тем же 403, с типовым `my-app/1.0` — 400 `Bad User-Agent: blacklisted`.

Токен выдаётся после **модерации приложения** на https://dev.hh.ru/admin, и
форма регистрации спрашивает, работодатель вы или вендор HR-решения. То есть
доступ рассчитан на работодателей и рекрутинговые сервисы; одобрят ли заявку
соискателю — заранее не известно, нужно подать и посмотреть.

Методы для соискателя в документации есть и описаны в OpenAPI
(https://api.hh.ru/openapi/redoc):

- `POST /negotiations` — откликнуться на вакансию (`vacancy_id`, `resume_id`,
  `message`). Требует OAuth-токен соискателя, то есть то же зарегистрированное
  приложение. Отклик на вакансии с **обязательным тестом через API невозможен**.
- `GET /negotiations?status=active` — свои отклики и их состояния, нужно для
  Фазы 4 (отслеживание ответов и приглашений).
- `GET /resumes/mine` — список своих резюме, оттуда `resume_id`.

**Про правила — отдельный разбор в `docs/hh-application.md`.** Коротко:
соискателю API не запрещён (п. 1.5 и 3.8 Условий API прямо разрешают
приложение соискателя для личных нужд), но п. 6.2.2 Условий сайта
**предписывает** программе работать только через API, а п. 6.1.34 и 6.1.38
запрещают имитацию работы пользователя и автоматический сбор информации
с сайта. Поэтому режим по умолчанию у hh.ru — `manual`, а не `rss`.

**Что работает без регистрации — официальный RSS поиска.** Публичный канал
самой площадки, но под п. 6.1.38 он формально тоже попадает, поэтому включать
его только после ответа hh (вопрос отправлен, см. `docs/hh-application.md`):

```
$ curl -s "https://hh.ru/search/vacancy/rss?text=python" | head -5
200  <rss version="2.0"> ... <item><pubDate>…</pubDate><title>…</title><link>https://hh.ru/vacancy/138952520</link>
```

Отдаёт `title`, `link`, `pubDate` — хватит, чтобы находить и накапливать
вакансии, но **не хватит, чтобы их оценивать**: ни вилки, ни требований, ни
описания. Без токена Matcher по hh.ru сможет работать только по заголовку,
а это заведомо плохая оценка.

**Решение по ТЗ (п. 2 «Соблюдение правил площадок»):** страницу вакансии
не парсим, даже технически это несложно — это обход закрытого доступа.
Поэтому hh.ru живёт в трёх режимах, переключаемых в конфиге:

- `access: api` — приложение одобрено, работает всё;
- `access: rss` — находим вакансии, в отчёт идут заголовок, ссылка и дата,
  оценка помечается как «нет данных», отклик — черновик + ссылка;
- `access: manual` — по умолчанию: я сам кидаю ссылки/текст вакансий, агент
  оценивает и готовит письмо.

## SuperJob

Регистрация приложения **самостоятельная**, без модерации под работодателя:
https://api.superjob.ru/register/. Без ключа:

```
$ curl -s "https://api.superjob.ru/2.0/vacancies/?keyword=python&count=1"
403  {"error":{"code":403,"message":"Необходимо передать ключ приложения.
      Зарегистрироваться можно по адресу https://api.superjob.ru/register/"}}
```

Нужные методы (все подтверждены в живой документации https://api.superjob.ru/):

- `GET /2.0/vacancies/` — поиск. Параметры, которые нам пригодятся:
  `keyword`, `town`, `catalogues`, `payment_from`, `no_agreement=1`,
  `type_of_work`, `place_of_work`, `experience`, `order_field=payment`,
  `page`/`count`. Заголовок `X-Api-App-Id: <секретный ключ>`.
- `GET /2.0/vacancies/:id/` — одна вакансия целиком.
- `POST /2.0/oauth2/password/` — токен по логину и паролю своего аккаунта
  (удобно для личного инструмента, без возни с redirect_uri);
  `/2.0/oauth2/access_token/` и `/refresh_token/` — обычный OAuth.
- `GET /2.0/user_cvs/` — свои резюме, оттуда `id_cv`.
- **`POST /2.0/send_cv_on_vacancy/`** — отклик соискателя. Это главная находка:
  у SuperJob легальный автоотклик есть.

  ```
  POST /2.0/send_cv_on_vacancy/ HTTP/1.1
  Host: api.superjob.ru
  X-Api-App-Id: <секретный ключ приложения>
  Authorization: Bearer <токен соискателя>
  Content-Type: application/x-www-form-urlencoded

  id_cv=25903399&id_vacancy=26747390&comment=The+Test
  → {"result": true}
  ```

  `id_cv` и `id_vacancy` обязательны, `comment` (сопроводительное) — нет.
  Повторный отклик площадка отбивает своим 403 «Операция невозможна в данный
  момент» — но на свой запрет повторов это не перекладываем, своя таблица
  `applications` всё равно нужна.
- `GET /2.0/messages/` и `/2.0/messages/history/all/:id/` — переписка с
  работодателем, то есть ответы и приглашения для Фазы 4.

Явных числовых лимитов запросов документация не публикует. Берём свои:
пауза `request_delay_seconds` между запросами и `max_requests_per_minute`
в `config/settings.yaml`, плюс отступ по 429/5xx.

## Работа.ру

`https://api.superjob.ru`-подобный шлюз есть (`https://api.rabota.ru/` отвечает
200, неизвестный метод отдаёт аккуратный `ENDPOINT_NOT_FOUND`), но это
**партнёрский** интерфейс: публичной документации и самостоятельной
регистрации ключа нет. Пока площадка выключена в конфиге. Если понадобится —
подаём заявку как партнёр, до тех пор режим «черновик + ссылка».

## Что из этого следует для ТЗ

1. **SuperJob становится основной площадкой**, а не второй: только там
   сквозной путь «нашли → оценили → откликнулись» работает официально.
2. **hh.ru без одобренного приложения — это поиск по RSS и черновики.**
   Нужно подать заявку на https://dev.hh.ru/admin и дождаться ответа;
   пока её нет, `platforms.hh.access: rss`.
3. Пункт 10 критериев приёмки «дневной лимит и порог соблюдаются» проверяется
   на SuperJob; для hh.ru в режиме `rss` отправки нет вообще.
