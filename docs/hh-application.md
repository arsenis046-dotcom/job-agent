# Заявка на приложение hh.ru: что писать и на что опираться

Прочитаны два документа целиком (29.10.2026):

- «Условия использования сервиса API» — https://dev.hh.ru/admin/developer_agreement
- «Условия использования сайта» — https://hh.ru/terms (на них ссылается п. 4.1 первых)

Саму форму регистрации посмотреть не удалось: она за входом в аккаунт, а
входить под тобой я не буду. Поэтому ниже готовый текст, который нужно
вставить в поля заявки, и разбор того, что в этих документах важно для нас.

## Хорошая новость: соискателю API не запрещён

Вопреки ощущению от формы регистрации, Условия прямо предусматривают наш случай:

- **Разработчиком приложения может быть любой пользователь сети интернет**
  (преамбула), а п. 1.2 прямо называет адрес `hh.ru/auth/applicant`
  «для соискателей» как способ получить учётную запись разработчика.
- **п. 1.5:** «Конечными пользователями Приложения могут быть юридические и
  физические лица, являющиеся как работодателями… так и **соискателями**».
- **п. 3.8:** «Разработчик приложения вправе использовать Приложение для
  **собственных (личных) нужд**».
- **п. 3.3:** использование материалов допустимо для целей, соответствующих
  тематике сайта — «поиск работы, сотрудников, получение информации о рынке
  труда». Наш случай — ровно первый и третий пункты.

Главный риск отказа не в запрете, а в п. 1.6: hh вправе отказать, если
есть основания полагать, что приложение используется **не только** для
трудоустройства. А п. 1.6.1 перечисляет примеры «правильного» использования
только со стороны работодателя: публикация вакансий, приглашение соискателя,
поиск по базе резюме. Аналога для соискателя там нет. Поэтому в заявке надо
снять этот вопрос заранее: один пользователь, трудоустройство этого
пользователя, никаких резюме чужих людей, никакой базы на продажу.

## Плохая новость: другого легального пути нет

- **п. 6.1.34 Условий сайта:** «не использовать программные средства,
  имитирующие работу пользователя на Сайте». Playwright и прочая эмуляция
  браузера — прямо запрещены.
- **п. 6.1.38:** «не производить автоматизированный сбор и структурирование
  информации с Сайта при помощи программ или сервисов парсинга, скрапинга
  или их аналогов».
- **п. 6.2.2:** «Для работы с Сайтом плагин для браузеров/программное
  приложение **должно** осуществлять взаимодействие с Сайтом через специально
  созданного для этих целей Интерфейса программирования приложений (API)».

То есть для программы путь прямо предписан один: зарегистрированное
приложение и API. Это стоит знать до того, как кто-то предложит «ну хотя бы
RSS почитать».

**Про RSS я был неосторожен.** В Фазе 0 я поставил `hh.access: rss` как
безопасный режим по умолчанию, считая публичный RSS официальным каналом.
Буква п. 6.1.38 шире: чтение RSS программой — это тоже «автоматизированный
сбор и структурирование информации с Сайта при помощи программ». Технически
RSS отдаётся и предназначен для машин, но решать это не мне и не тебе —
это вопрос к hh. Поэтому:

- по умолчанию поставил `hh.access: manual` (вакансии приносишь ты сам,
  агент оценивает и готовит письмо);
- `rss` остаётся в коде и включается одной строкой, если hh ответит, что
  публичный RSS читать можно;
- вопрос про RSS включён в письмо на `api@hh.ru` ниже.

## Что нужно поправить в коде до того, как приложение начнёт работать

Эти пункты Условий — не формальности, они меняют поведение программы:

| Пункт | Требование | Что делаем |
|---|---|---|
| 4.9 | приложение не должно вызывать активные действия в API **без ведома и согласия** авторизуемого пользователя | режим `auto` остаётся выключенным по умолчанию и включается отдельной командой; каждый отклик пишется в `applications` с текстом письма |
| 3.11 | следить за актуальностью данных, **своевременно удалять архивные вакансии** | в Фазе 2 нужен шаг «обновить/заархивировать»: вакансия, ушедшая в архив, удаляется из базы. В ТЗ этого шага не было |
| 4.3 | нельзя формировать базу данных для предоставления её другим лицам | база локальная, только моя, наружу не отдаётся — записать в CLAUDE.md |
| 4.6 | единственный пользователь полученных данных — тот пользователь hh.ru, для которого данные получены; **передавать их сторонним сервисам запрещено** | **см. ниже, это отдельный разговор** |
| 3.6 | запрещено собирать и хранить логины и пароли пользователей Сайта | для hh — только OAuth. Заодно: у SuperJob я заложил логин с паролем в `.env`; это их площадка и их правила, но привычку стоит сменить на OAuth-код там, где он есть |
| 1.4 | если приложением пользуются физлица в поиске работы, в форме регистрации новых пользователей нужен чек-бокс про «Соглашение об оказании услуг по содействию в трудоустройстве» | у нас регистрации новых пользователей нет вообще: пользователь один и это я. В заявке это надо сказать прямо, чтобы не выглядело уклонением |

### Отдельно: оценка вакансий моделью — это передача данных стороннему сервису

Пункт 4.6 запрещает передавать полученные через API данные сторонним
сервисам. А Matcher по ТЗ отправляет текст вакансии в Anthropic API, то есть
именно стороннему сервису. Формально это тот самый пункт.

Доводы в нашу пользу: данные не распространяются, а обрабатываются в
интересах того же самого пользователя, для которого получены (п. 4.6 про
«единственных пользователей данных» — пользователь один, это я);
вакансии — не персональные данные соискателей, а публичные объявления.
Но буквального разрешения там нет, и я не юрист.

Варианты, из которых надо выбрать осознанно:

1. **Спросить hh** письмом на `api@hh.ru` (текст ниже) — самый чистый путь.
2. **Отправлять в модель минимум:** не весь текст вакансии, а выжимку
   требований; снижает риск, но не снимает вопрос.
3. **Оценивать hh-вакансии без модели:** сверка по ключевым словам
   профиля локально, моделью оценивать только SuperJob. Бесплатно и
   безопасно, но оценка грубее.

Моя рекомендация: пункт 1, а пока ответа нет — пункт 3 для hh.ru.
Для SuperJob вопрос не стоит: у них в правилах такого запрета я не нашёл.

## Текст для формы заявки

**Название приложения:** `Job Agent (личный помощник в поиске работы)`

**Описание** — главное поле, по нему и будут решать:

> Приложение для личного использования одним человеком — мной, автором
> приложения, зарегистрированным на hh.ru как соискатель. Помогает мне
> самому искать работу: находит вакансии по моим ключевым словам, сравнивает
> их с моим резюме, показывает мне список с обоснованием, и по моему
> подтверждению отправляет отклик на выбранные вакансии с сопроводительным
> письмом.
>
> Конечный пользователь один — я. Регистрации других пользователей в
> приложении нет и не планируется, поэтому форма регистрации новых
> пользователей и чек-бокс по п. 1.4 Условий отсутствуют за ненадобностью.
> Приложение работает локально на моём компьютере, веб-сервиса и публичного
> доступа у него нет.
>
> Что приложение делает: поиск вакансий (GET /vacancies), чтение вакансии
> (GET /vacancies/{id}), список моих резюме (GET /resumes/mine), отклик
> (POST /negotiations), чтение состояния моих откликов
> (GET /negotiations) — чтобы видеть ответы и приглашения.
>
> Чего приложение не делает: не обращается к базе резюме других людей, не
> публикует вакансии, не формирует и не передаёт никому базу данных,
> не показывает полученные данные третьим лицам, не имитирует работу
> пользователя на сайте и не парсит страницы — всё взаимодействие только
> через API. Отклики отправляются по одному, с паузами между запросами и
> с суточным лимитом, и каждый — после моего подтверждения (п. 4.9 Условий).
> Вакансии, ушедшие в архив, удаляются из локальной базы (п. 3.11).
>
> Цель использования — исключительно моё собственное трудоустройство
> (п. 3.3, п. 3.8 Условий) и понимание рынка труда по моей специальности.

**Тип приложения:** локальное, без публичного веб-интерфейса.
**Redirect URI:** `http://localhost:8765/callback` (локальный адрес для
получения OAuth-кода; постоянный домен приложению не нужен).
**Контактный email:** твой почтовый адрес — на него придёт решение (п. 1.7)
и он же пойдёт в `User-Agent`, как требует hh.

Если в форме есть выбор «кто вы» с вариантами про работодателя и вендора
HR-решений — не подбирай ближайший. Выбирай вариант про частное лицо или
разработчика для себя, а если такого варианта нет, напиши в описании первой
строкой «Приложение соискателя для личного использования, п. 1.5 и 3.8
Условий» и отправляй. Притворяться сотрудником работодателя нельзя: это
п. 3.10 (введение в заблуждение) и основание для отказа и блокировки.

## Письмо на api@hh.ru

Отправить можно сразу, не дожидаясь решения по заявке, — это снимет оба
спорных вопроса:

> Здравствуйте!
>
> Я подал заявку на регистрацию приложения «Job Agent» — личного помощника
> в поиске работы для одного пользователя (меня). Прошу уточнить два момента
> по Условиям использования, чтобы не нарушить их по незнанию.
>
> 1. Пункт 6.1.38 Условий использования сайта запрещает автоматизированный
> сбор информации с Сайта программами. Распространяется ли этот запрет на
> чтение программой публичного RSS поиска вакансий
> (https://hh.ru/search/vacancy/rss?text=...), или RSS можно считать
> предоставленным для машинного чтения каналом?
>
> 2. Пункт 4.6 Условий использования сервиса API запрещает передавать
> полученные через API данные сторонним сервисам. Считается ли нарушением
> отправка текста вакансии (публичного объявления, без персональных данных
> соискателей) во внешний сервис обработки текста, если результат получает
> только тот же самый пользователь, для которого вакансия была получена,
> и никому больше не передаётся?
>
> Заранее спасибо.

## Чего ждать

- Срок ответа по заявке Условия прямо не называют; для обжалования и для
  спорных обращений назван срок **не более 15 календарных дней** (п. 1.8, 2.3).
- Число одновременных заявок в рассмотрении ограничено — интерфейс
  dev.hh.ru прямо говорит «Достигнут лимит заявок в статусе рассмотрения».
  Значит, подавать надо одну и хорошо.
- **Отказ — не конец.** П. 1.8: можно подать повторную заявку с
  обоснованием, и отказ обязаны объяснить с указанием конкретных нарушенных
  пунктов (п. 1.7). То есть если откажут — у нас будет текст причины, и
  вторая заявка пишется уже по нему.
- Пока решения нет, hh.ru живёт в режиме `manual`, а Фазы 1–3 строятся на
  SuperJob. Ничего не простаивает.
