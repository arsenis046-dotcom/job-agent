# hh.ru: API для соискателей закрыт. Что это значит для проекта

**Вывод: заявку на приложение подавать не нужно.** Честно заполнить форму
соискателю нельзя, а если бы и удалось — отклики через API для соискателей
всё равно отключены. hh.ru остаётся в режиме `manual`: вакансии приношу я,
агент оценивает и готовит письмо, отклик отправляется руками на сайте.

Ниже: что именно показала форма, почему решение такое, и какие пункты правил
продолжают управлять кодом.

## Что показала форма заявки

Форма `dev.hh.ru/admin` (увидена 29.10.2026) в разделе «Приложением будут
пользоваться» даёт только два варианта:

> ○ Только сотрудники работодателя \*
> ○ Сотрудники нескольких работодателей \*
>
> \* Обратите внимание, **поддержка API для соискателей прекращена
> 15 декабря 2025**

Варианта «частное лицо» или «соискатель для себя» в форме **нет**.

## Почему мы не подаём заявку

**Любой из двух вариантов — заведомо ложное утверждение.** Приложением будет
пользоваться один человек для собственного трудоустройства; он не сотрудник
работодателя, который ищет персонал. Указать иное — это п. 3.10 Условий
(«запрещается распространять недостоверную информацию о Приложении или
вводить в заблуждение о функциональных возможностях») и прямое основание
для отказа, а после обнаружения — для отзыва ключа по п. 2.3.

В обсуждениях такой обход советуют открытым текстом: «главное не выдавайте
в себе соискателя». Это ровно то, чего мы не делаем. Принцип из ТЗ —
«прохождение ATS честным путём» и «соблюдение правил площадок» — не про
аккуратность формулировок, а про то, что мы не врём площадке даже когда
это сработало бы.

**И это всё равно не дало бы автоотклика.** По свидетельству человека,
который разбирался с ограничениями, закрыта именно возможность совершать
действия: отклики и прочие изменения на сайте для соискателя отключены,
а GET-методы на выборку остались. То есть даже одобренное приложение дало бы
только чтение вакансий, а `POST /negotiations` из нашего коннектора всё
равно не работал бы.

Поэтому заявка не просто рискованная — она бесполезная для нашей задачи.

## Что остаётся

1. **`hh.ru` в режиме `manual`** (так и настроено в `config/settings.yaml`):
   агент сам ничего не запрашивает, я приношу ссылку или текст вакансии,
   он оценивает и готовит письмо, отклик я отправляю на сайте руками.
   Оценка для hh.ru делается **локальным** движком — см. ниже про п. 4.6.
2. **Письмо в `api@hh.ru`** (текст ниже) — спросить напрямую, есть ли
   легальный путь для личного приложения соискателя после 15.12.2025.
   Может оказаться, что путь есть и он просто не вынесен в форму.
3. **SuperJob — единственная площадка с полным циклом.** Там отклик
   соискателя доступен официально (`POST /2.0/send_cv_on_vacancy/`),
   см. `docs/superjob-application.md`.

Прежняя редакция этого файла утверждала обратное: «соискателю API не
запрещён», со ссылкой на п. 1.5 и 3.8 Условий, где конечными пользователями
прямо названы соискатели, а личное использование разрешено. Условия
датированы 19.01.2023 и этого запрета действительно не содержат — но форма
2026 года говорит иначе, и операционная реальность за ней. Я ошибся,
опираясь на документ, а не на то, что показывает интерфейс.

## Пункты правил, которые продолжают управлять кодом

Независимо от заявки эти требования действуют, и они уже отражены в коде:

| Пункт | Требование | Где у нас |
|---|---|---|
| 6.2.2 Условий сайта | программа обязана работать через API, а не через сайт | `access: manual`, парсинга нет |
| 6.1.34 | нельзя имитировать работу пользователя на сайте | эмуляции браузера нет |
| 6.1.38 | нельзя автоматизированно собирать информацию с сайта | **в том числе чтение RSS программой** — поэтому `rss` не включён |
| 4.6 Условий API | нельзя передавать полученные данные сторонним сервисам | `use_model: false` у hh.ru: модель — сторонний сервис |
| 4.9 | никаких активных действий без ведома пользователя | `auto` включается только командой `mode auto --yes` |
| 3.11 | своевременно удалять архивные вакансии | команда `jobagent prune` |
| 4.3 | нельзя формировать базу данных для передачи другим | база локальная, наружу не отдаётся |

Проверка `test_текст_вакансии_hh_не_уходит_в_модель` падает, если
`use_model` для hh.ru переключить, — это проверено подменой значения.

и разрешает hh делать самостоятельно.

## Сроки и отказы, если дело всё же дойдёт до заявки

- Форма обещает ответ за несколько рабочих дней, в редких случаях до
  15 рабочих дней. На практике в обсуждениях называют от суток до четырёх.
- Отказ приходит с указанием пункта: например, по п. 1.3 за недостаточно
  подробно заполненные поля. По п. 1.8 можно подать повторную заявку,
  устранив причину, и отказ обязаны объяснить (п. 1.7).
- Число одновременных заявок ограничено: интерфейс пишет «Достигнут лимит
  заявок в статусе рассмотрения».
