# Телеграм-каналы как источник вакансий

Появился потому, что hh.ru закрыл API для соискателей (`docs/hh-application.md`),
а искать всё равно надо. Выяснилось попутно, что это не замена из нужды:
в обсуждениях рынка люди пишут, что активность и более высокие вилки ушли
в Telegram и подобные каналы, пока hh забит автоотказами.

## Почему это законно, в отличие от парсинга hh.ru

ТЗ требует «только официальные API». Telegram сам предоставляет интерфейс
для чтения — MTProto, документирован на core.telegram.org, — и мы читаем
через него, под своим аккаунтом, те публичные каналы, на которые и так
можно зайти. Это не обход закрытого доступа: доступ открыт, интерфейс
предоставлен владельцем платформы.

Веб-превью `t.me/s/<канал>` мы **не** парсим, хотя это было бы проще:
по той же причине, по которой не читаем RSS hh.ru.

## Настройка

1. Получить `api_id` и `api_hash` на https://my.telegram.org →
   API development tools. Это делается один раз и бесплатно.
2. Вписать их в `.env` (`TELEGRAM_API_ID`, `TELEGRAM_API_HASH`).
3. Войти в аккаунт:

   ```bash
   uv run jobagent telegram login
   ```

   Телефон и код спросит сам Telethon, и вводишь их ты. Ни телефон, ни код,
   ни облачный пароль агент не видит и не хранит.
4. Проверить каналы:

   ```bash
   uv run jobagent telegram channels
   ```

   Покажет по каждому каналу, сколько постов за неделю и сколько из них
   опознано как вакансии. Если у канала ноль вакансий при непустых постах —
   либо канал не про вакансии, либо разбор не справляется с его форматом.
5. Включить площадку: `platforms.telegram.enabled: true` в
   `config/settings.yaml`. По умолчанию выключена — без входа читать нечем.

**Файл сессии равен доступу к аккаунту.** Он в `.gitignore` (`*.session`),
лежит в `output/`, никуда не отправляется. Отдавать его никому нельзя;
если он утёк — отозвать сеансы в настройках Telegram.

## Каналы

Список в `config/settings.yaml`, `platforms.telegram.channels` — имена без `@`.
Пять каналов записаны как заготовка, и их **надо проверить**: каналы
переезжают, закрываются и меняют тематику. `jobagent telegram channels`
покажет, какие из них живы и дают вакансии.

Канал в списке не обязан быть айтишным: смена сферы поиска — это другой
профиль поиска плюс другие каналы, и кода это не касается.

## Чего ждать от разбора

Канал — это не API: там нет полей, есть текст, который каждый автор пишет
как хочет. Поэтому `telegram_posts.py` делает немного и честно:

- **опознаёт вакансию** по признакам в тексте (нужно хотя бы два из
  «требования», «обязанности», «зарплата», «удалённо», «разработчик» и
  прочих) и отбрасывает служебные посты — дайджесты, рекламу, розыгрыши;
- **вытаскивает заголовок** — первую осмысленную строку, без эмодзи,
  хештегов и слова «Вакансия»;
- **разбирает вилку**: «от 150 000 ₽», «от 150 000 до 220 000 ₽»,
  «150 000 - 220 000 руб», «150–200к» (это тысячи, а не сто пятьдесят
  рублей), «$3000»;
- **собирает контакты** (`@ник`) и ссылки — по ним и отвечают;
- **весь текст поста остаётся описанием**, так что оценивать есть что,
  даже если разбор чего-то не понял.

У каждого отказа есть написанная причина — видно, почему пост не попал
в выдачу.

Перепечатки отбрасываются: одну вакансию публикуют несколько каналов,
и в пределах запуска считается отпечаток по тексту.

## Откликов здесь нет

В каналах отвечают письмом или в личку человеку, поэтому у площадки всегда
`apply: draft`. Агент оценивает вакансию и готовит письмо, а отправляю я
сам — контакт лежит в `raw.contacts` и в тексте вакансии. Это природа
канала, а не недоделка: автоматически писать незнакомым людям в личку
не стоит и по правилам Telegram, и по-человечески.

Оценка моделью здесь разрешена (`use_model: true`): пост в публичном
канале — не данные, полученные по API площадки с ограничениями на передачу.
