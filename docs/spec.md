# ТЗ: Job Agent, персональный ассистент по поиску работы

Ты Claude Code. Построй локальное приложение «Job Agent» по этому ТЗ. Работай по фазам (раздел 9), после каждой фазы останавливайся, запускай тесты и показывай результат. Не переходи к следующей фазе без моего «ок».

## 1. Цель

Универсальный ассистент для поиска работы. Стартовое направление: vibe coding (разработка с помощью ИИ-инструментов: Claude Code, Cursor и т. п.). Ассистент должен:

1. Помочь составить честное сильное резюме на основе моих реальных данных.
2. Искать вакансии на hh.ru и SuperJob / Работа.ру.
3. Оценивать вакансии на соответствие и отсеивать лишнее.
4. Под каждую вакансию адаптировать резюме и писать сопроводительное письмо.
5. Автоматически откликаться в рамках лимитов.
6. Анализировать рынок и предлагать лучшие вакансии.
7. По приглашениям на собеседование давать конкретные советы по подготовке.
8. Легко перестраиваться на другую сферу поиска сменой конфигурации, без правки кода.

## 2. Принципы

- **Правда в резюме.** Единственный источник фактов обо мне: `profile/master_profile.yaml`. Агентам запрещено добавлять опыт, навыки, цифры, должности, компании или образование, которых там нет. Если факта нет, агент задаёт мне вопрос.
- **Мой опыт: только пет-проекты, коммерческого найма нет.** Резюме честно подаёт их как проекты: что построено, стек, результат, ссылка на репозиторий или демо. Не маскировать их под коммерческий опыт.
- **Прохождение ATS честным путём.** Простой одноколоночный формат, стандартные заголовки, текстовый слой, формулировки навыков как в вакансии (только для навыков, которые у меня реально есть). Не использовать скрытый белый текст, невидимые ключевые слова, выдуманный опыт, массовый спам и приёмы против правил площадок.
- **Соблюдение правил площадок.** Только официальные API (OAuth-токены, заголовок User-Agent, лимиты запросов). Никакого скрейпинга с обходом защиты и никакой эмуляции браузера для откликов. Если API площадки не позволяет откликаться, режим для неё автоматически «только черновики».
- **Безопасность по умолчанию.** Режим `dry_run` включён по умолчанию. Секреты только в `.env` (в `.gitignore`), токены никогда не попадают в логи и в промпты.

## 3. Принятые решения

| Вопрос | Решение |
|---|---|
| Площадки | hh.ru, SuperJob / Работа.ру (расширяемая архитектура коннекторов) |
| Отправка откликов | Автомат с лимитом: сам отправляет отклики с оценкой выше порога, не больше N в день. По умолчанию N=10 и порог 70/100, всё в конфиге |
| Мой опыт | Только пет-проекты. Нужен модуль, который помогает выбрать и упаковать проекты в портфолио |
| Запуск | Локально на ПК, по расписанию (cron / Task Scheduler) и вручную через CLI |

## 4. Стек

- Python 3.12, `uv` для зависимостей.
- CLI на Typer; локальное хранилище SQLite (SQLAlchemy или sqlite3 + pydantic-модели).
- Конфиги в YAML; валидация через pydantic.
- LLM: Anthropic SDK (модель задаётся в конфиге, по умолчанию Sonnet; для сложного анализа можно Opus). Структурированный вывод через tool use / JSON-схемы.
- Генерация резюме: DOCX (python-docx) и PDF с текстовым слоем. Шаблон одноколоночный.
- Тесты: pytest; HTTP-мокирование (respx / responses).

## 6. Гибкая смена сферы: профили поиска

Вся специфика сферы живёт в `config/search_profiles/<name>.yaml`, а не в коде:

```yaml
name: vibe_coding
keywords: ["vibe coding", "AI-разработчик", "разработчик с ИИ", "промпт-инженер", "LLM", "no-code", "автоматизация"]
exclude_keywords: ["senior", "lead", "5+ лет"]   # настройте под себя
regions: []            # TODO: заполнить
schedule: []           # remote / hybrid / office
salary_min: null       # TODO
employment: []         # полная / частичная / проектная
must_have_skills: []
nice_to_have_skills: []
deal_breakers: []      # стоп-факторы
score_threshold: 70
```

Команда `jobagent profile switch <name>` меняет активный профиль. Команда `jobagent profile new` запускает диалог (через LLM) и создаёт профиль под новую сферу, заодно предлагает, какие факты из мастер-профиля там важны.

## 7. Агенты (субагенты и их роли)

Каждый агент это отдельный промпт-файл + pydantic-схема входа/выхода. Для разработки и ручных запусков продублируй их как субагентов в `.claude/agents/`. Независимые вызовы (например, оценка пачки вакансий) делай параллельно.

1. **Profile Builder.** Интервьюирует меня, заполняет и обновляет `master_profile.yaml`, спрашивает недостающие факты, не выдумывает. Помогает упаковать пет-проекты: цель, стек, что именно сделал я, результат, ссылка.
2. **Portfolio Advisor.** Анализирует рынок и мой профиль, предлагает 3–5 пет-проектов, которые закроют самые частые требования вакансий, и формулировки для README.
3. **Scout.** Ищет вакансии через коннекторы по активному профилю, дедуплицирует, пишет в БД.
4. **Matcher.** Оценивает вакансию 0–100 с обоснованием: совпавшие требования, пробелы, стоп-факторы, вердикт (откликаться / пропустить / спросить меня).
5. **Resume Writer.** Из мастер-профиля формирует базовое резюме и вариант под конкретную вакансию (переупорядочивает и переформулирует, не добавляя фактов).
6. **Letter Writer.** Пишет короткое (до ~150 слов) письмо с конкретикой из вакансии и из моих проектов, без шаблонных фраз.
7. **Fact Checker (Reviewer).** Обязательный шаг перед отправкой: сверяет каждое утверждение в резюме и письме с мастер-профилем и блокирует отправку при расхождении. Это отдельный вызов с чистым контекстом.
8. **Applier.** Отправляет отклик через API с учётом лимитов, пауз между запросами, защиты от повторных откликов, логирует результат.
9. **Market Analyst.** Раз в неделю строит отчёт: динамика числа вакансий, вилки зарплат, самые частые навыки и инструменты, растущие и падающие запросы, рекомендации, что подтянуть.
10. **Interview Coach.** Для каждого приглашения: разбор вакансии и компании, вероятные вопросы, технические темы, задачи для практики, вопросы работодателю, как честно говорить про отсутствие коммерческого опыта, чек-лист на день собеседования.

## 8. Данные и логирование

Таблицы SQLite: `vacancies`, `scores`, `applications` (вакансия, версия резюме, текст письма, статус, дата, ответ), `market_snapshots`, `interviews`. Для каждого отклика сохраняй точные тексты резюме и письма, чтобы я мог их перечитать. Логи без секретов.

## 9. Фазы разработки

**Фаза 0. Каркас.** Репозиторий, `CLAUDE.md`, конфиги, CLI-скелет, БД, `.env.example`, тесты-заглушки.
**Фаза 1. Профиль и резюме.** Profile Builder, мастер-профиль, Resume Writer, рендер DOCX/PDF, проверка ATS-читаемости (извлечь текст из PDF и убедиться, что порядок и заголовки корректны). Остановка: я проверяю резюме.
**Фаза 2. Поиск и оценка.** Коннекторы hh.ru и SuperJob (только чтение), Scout, Matcher, отчёт в `output/` в виде таблицы. Остановка: я проверяю, насколько оценки соответствуют моим ожиданиям, и мы калибруем порог.
**Фаза 3. Отклики.** Letter Writer, Fact Checker, Applier, режимы `dry_run` / `approve` / `auto`, лимиты. Сначала только `dry_run` и `approve`. `auto` включается отдельной командой после моего подтверждения.
**Фаза 4. Аналитика и подготовка.** Market Analyst, Portfolio Advisor, Interview Coach, еженедельный дайджест.
**Фаза 5. Смена сферы.** `profile switch/new`, проверка на втором тестовом профиле, не связанном с IT.

## 10. Критерии приёмки

- В `dry_run` ни один запрос на отправку отклика не уходит (проверено тестом).
- Fact Checker на тестовом наборе с подброшенным ложным фактом блокирует отправку.
- Дубликаты откликов на одну вакансию невозможны.
- Дневной лимит и порог соблюдаются (тест).
- Смена профиля поиска не требует правки кода.
- Токены и ключи отсутствуют в логах, БД и сгенерированных документах.
- При ошибках API (401, 429, 5xx) работа продолжается с понятным сообщением, без потери данных.
