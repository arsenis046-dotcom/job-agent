# Правила работы в этом репозитории

Job Agent — личный ассистент по поиску работы. Полное ТЗ — `docs/spec.md`,
что реально умеют API площадок — `docs/api_notes.md` (проверено запросами,
а не по памяти; при сомнениях перепроверять живьём и обновлять файл).

## Нерушимое

1. **Единственный источник фактов обо мне — `profile/master_profile.yaml`.**
   Запрещено добавлять в резюме и письма опыт, навыки, цифры, должности,
   компании, образование и сроки, которых там нет. Нет факта — агент задаёт
   вопрос пользователю и останавливается, а не придумывает.
2. **Коммерческого найма у меня нет, только пет-проекты.** Подавать их как
   проекты: что построено, стек, моя роль, результат, ссылка. Не маскировать
   под работу по найму, не писать «опыт 3 года».
3. **Никакого скрейпинга и эмуляции браузера.** Только официальные API и
   официальные публичные каналы (RSS поиска hh.ru). Если площадка закрыла
   доступ — это режим «черновик + ссылка», а не повод обойти защиту.
   Никаких скрытых ключевых слов, белого текста и прочих приёмов против ATS.
4. **`dry_run` по умолчанию.** Любая отправка наружу идёт через
   `jobagent.connectors.base.Connector.apply()` и обязана проверять
   `settings.mode`. Новый код, который умеет отправлять, обязан получить тест,
   доказывающий, что в `dry_run` запрос не уходит.
5. **Секреты только в `.env`.** В логи, в БД, в промпты и в сгенерированные
   документы токены не попадают. Перед коммитом — `git diff` на ключи.
6. **Fact Checker обязателен перед отправкой** и вызывается с чистым
   контекстом: он сверяет каждое утверждение с мастер-профилем и блокирует
   отправку при расхождении.

## Как устроен код

- `src/jobagent/config.py` — загрузка и валидация YAML через pydantic.
  Ни одного «магического числа» в коде: лимиты, порог, модель, режимы — в
  `config/settings.yaml`, специфика сферы — в `config/search_profiles/*.yaml`.
- `src/jobagent/db.py` — SQLite, схема в одном месте, миграции идемпотентные
  (`CREATE TABLE IF NOT EXISTS`), версия схемы в таблице `meta`.
- `src/jobagent/connectors/` — по файлу на площадку, общий интерфейс в
  `base.py`. Новая площадка не должна требовать правок в `pipeline.py`.
- `src/jobagent/agents/` — промпт + схема входа/выхода на каждого агента.
  Структурированный вывод через tool use, не через «распарсить текст».
- Смена сферы поиска не должна требовать правки кода. Если для нового профиля
  понадобился код — значит, что-то зашито не там.

## Рабочие привычки

- Фазы разработки — раздел 9 ТЗ. После фазы остановиться, прогнать тесты,
  показать результат и дождаться «ок».
- Тесты: `uv run pytest`. HTTP только через `respx` — живых запросов к
  площадкам в тестах нет.
- Зависимости: `uv`. Запуск: `uv run jobagent <команда>`.
- Перед написанием кода, который зовёт Anthropic API, прочитать скилл
  `claude-api` (актуальные идентификаторы моделей и параметры), а не
  полагаться на память.
- Вся переписка и комментарии в коде — по-русски, как и остальной проект.
