# Job Agent

Личный ассистент по поиску работы: ищет вакансии, оценивает их, собирает
резюме и сопроводительные письма из проверенных фактов о себе и — в пределах
лимитов — откликается. Стартовое направление: разработка с ИИ-инструментами.

ТЗ — `docs/spec.md`. Правила для Claude Code — `CLAUDE.md`.
**Что реально умеют API площадок — `docs/api_notes.md`, это читать первым.**

## Коротко про площадки (проверено 29.10.2026)

- **SuperJob** — основная площадка: поиск и отклик соискателя
  (`send_cv_on_vacancy`) доступны официально. Ключ выдаётся по заявке, и
  правила увязывают его с лицензионным вознаграждением — что заполнять
  в заявке, в `docs/superjob-application.md`.
- **hh.ru** — **API для соискателей закрыт с 15.12.2025**, о чём прямо
  сообщает форма регистрации приложения; публичный поиск отдаёт 403
  с апреля 2026. Поэтому режим `manual`: вакансии приносит пользователь,
  агент оценивает локально и готовит письмо, отклик отправляется руками.
  Разбор и письмо в api@hh.ru — `docs/hh-application.md`.
- **Работа.ру** — только партнёрский API, выключена.

## Запуск

```bash
uv sync
cp .env.example .env                                           # заполнить ключи
cp profile/master_profile.example.yaml profile/master_profile.yaml
uv run jobagent init
uv run jobagent doctor          # что настроено, что нет
uv run jobagent profile check   # что в мастер-профиле есть, чего не хватает
uv run jobagent resume          # собрать резюме: DOCX, PDF и проверка ATS
uv run jobagent search          # найти вакансии и записать в базу
uv run jobagent score           # оценить новые вакансии
uv run jobagent vacancies       # отчёт таблицей в output/
uv run jobagent prune           # убрать вакансии, которых больше нет в выдаче
uv run jobagent apply           # письма, проверка фактов, отклики по режиму
uv run jobagent mode            # показать режим; mode approve / mode auto --yes
uv run pytest
```

Поля мастер-профиля описаны в `docs/profile.md`, профили поиска —
в `docs/search-profiles.md`. Сменить сферу поиска:

```bash
jobagent profile new povar -k "повар" --title "Повар" --switch
```

## Состояние по фазам

| Фаза | Что | Статус |
|---|---|---|
| 0 | Каркас, конфиги, БД, CLI, тесты | готово |
| 1 | Profile Builder, Resume Writer, DOCX/PDF | готово, ждёт моих фактов |
| 2 | Коннекторы, Scout, Matcher | поиск, оценка и отчёт готовы; оценка пока локальная, без модели |
| 3 | Letter Writer, Fact Checker, Applier | готово; письмо пока собирается из фактов, без модели |
| 4 | Market Analyst, Portfolio Advisor, Interview Coach | — |
| 5 | Смена сферы поиска | готово, проверено на профиле вне IT |

## Режимы отправки

- `dry_run` (по умолчанию) — письма готовятся и сохраняются, наружу не уходит
  ничего. Проверено тестом: в этом режиме не выполняется ни один запрос.
- `approve` — отклик ждёт подтверждения.
- `auto` — отправляет сам всё, что выше порога, в пределах суточного лимита.
  Включается отдельной командой `jobagent mode auto --yes`: без `--yes`
  программа объясняет, что произойдёт, и ничего не меняет.

Перед любой отправкой обязательно проходит Fact Checker. Пока резюме не
сверено с мастер-профилем, не отправляется ничего; письмо проверяется для
каждой вакансии отдельно. Расхождение — отправка заблокирована, причина
записана в журнал.

## Главное правило

Факты обо мне берутся только из `profile/master_profile.yaml`. Чего там нет —
того нет в резюме. У каждой системы указано, где она сделана: рабочая задача
или свой проект, — и подменять одно другим нельзя ни в ту, ни в другую сторону.
`dry_run` включён по умолчанию; отправка наружу идёт единственным путём —
через `Connector.apply()`, и он проверяет режим.
